# مسح GitHub — ما يرفع جودة القرار فعلاً

> تاريخ المسح: 2026-08-20 · الروابط والرخص وقرارات القبول التفصيلية في `docs/source-register.md`.

## الحكم

المشروع لا يحتاج مكتبة أكبر. لديه 13 إطاراً تحت `vendor/wondelai/` ومهارات محلية تغطي الفرز والعرض
والتواصل والمال. الفجوة المثبتة كانت **سلطة الدليل وحلقة التنفيذ**، لا غياب عقلية مؤلف جديد.

## ما اعتُمد

### Markster OS

المفيد: بروتوكول أسبوعي يحدد القيد، ينفذ مساراً واحداً، يقيس تحركه، ثم يكرر أو ينتقل.
اعتُمد المبدأ بصياغة محلية في `docs/weekly-constraint-loop.md`. لم تُستورد أدوات البريد البارد أو
قوالب المقاييس لأنها تحتاج تكييفاً نظامياً وبيانات سوق محلية.

### Kai Marketing OS

المفيد: فصل وقوع التنفيذ عن جودة الصنعة وعن النتيجة التجارية، ومنع المؤلف من إصدار حكم نجاح نفسه.
اعتُمد المبدأ في `docs/evidence-standard.md`. لم تُستورد المنظومة أو بواباتها البرمجية.

## سياسة البحث القادم

لا يبدأ مسح GitHub عاماً. يبدأ من جملة فشل ميدانية مثل «خمس موافقات وصفر رد» أو «عرضان وصفر دفع».
يُقبل المصدر إذا كان مرخصاً، وقرئت المادة المحددة كاملة، وغيّر قراراً أو أضاف اختباراً قابلاً للتشغيل.
عدد النجوم وعدد الوكلاء وعدد المهارات ليست معايير ذكاء.
